DAY 01 / PART 1 / SOLVED

Follow the floor, one symbol at a time.

A tiny stream becomes a running sum. The trace is the algorithm made visible.

SOLVED

The idea: start at floor zero, add one for every opening parenthesis, subtract one for every closing parenthesis, and keep the last running total. The real input produced an answer Advent of Code accepted.

Running sum lab

Edit the stream, move through it, and watch one accumulator carry the whole computation.

Journal

The code is small. The record keeps the choice and the concept from disappearing with it.

Why Python

I chose Python because this level is almost pure iteration. It lets the running sum stay visible without setup code, and its standard library already has the small test runner I need. A more elaborate runtime would hide the idea rather than help it.

First idea

My first idea was also the implementation I kept: start at zero, consume the stream from left to right, add one for ( and subtract one for ). I exposed the intermediate floors as floor_trace, then made final_floor consume that trace.

Wrong turns

There were no wrong turns on this level. The public examples made the mapping and initial value unambiguous, and the direct running sum worked immediately. I did add explicit rejection of unexpected characters so malformed input cannot silently produce an answer.

Fold, then scan

A fold collapses the whole instruction stream into one accumulator. A scan exposes every intermediate accumulator. The solution needs the fold; this visualisation uses the scan.
